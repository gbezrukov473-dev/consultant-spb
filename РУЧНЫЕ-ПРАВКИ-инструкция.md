# Инструкция: что доделать вручную на сервере

Эти задачи **нельзя выполнить заливкой файлов** из репозитория — их делают на сервере
(в конфиге nginx / в файле `init.php`) и в админке Bitrix. Делайте по порядку.

Сервер: **nginx + 1С-Bitrix**, сайт `https://spbcons.ru/`.

---

## Шаг 0. Сначала — залить файлы и очистить кеш

Прежде чем делать ручные правки, выложите изменённые файлы из `public_html/`
(см. список в конце) и очистите кеш Bitrix:

1. Зайдите в админку: `https://spbcons.ru/bitrix/admin/`
2. **Настройки → Настройки продукта → Автокеширование → «Очистить файлы кеша»**
   (или откройте `https://spbcons.ru/bitrix/admin/cache.php` и нажмите «Очистить весь кеш»).

Без этого главная может ещё какое-то время отдаваться из кеша без изменений.

## Шаг 1. Last-Modified + 304 (пункт аудита 1.2)

**Зачем:** поисковики и браузеры экономят трафик и быстрее переобходят сайт, когда сервер
отдаёт заголовок `Last-Modified` и отвечает `304 Not Modified` на повторный запрос.
Сейчас динамические страницы Bitrix отдают `Cache-Control: no-store` без `Last-Modified`.

**Как (через Bitrix, рекомендуется):**

1. На сервере откройте (или создайте, если его нет) файл:
   ```
   /local/php_interface/init.php
   ```
   *(если в проекте используется старый путь — `/bitrix/php_interface/init.php`)*

2. Добавьте в конец файла этот код (перед закрывающим `?>`, если он есть):

   ```php
   use Bitrix\Main\EventManager;

   EventManager::getInstance()->addEventHandler(
       'main', 'OnEpilog',
       function () {
           // не трогаем админку и ajax
           if (defined('ADMIN_SECTION') && ADMIN_SECTION === true) return;
           if (!empty($_SERVER['HTTP_X_REQUESTED_WITH'])) return;

           $lastModified = @filemtime($_SERVER['SCRIPT_FILENAME']);
           if ($lastModified) {
               header('Last-Modified: ' . gmdate('D, d M Y H:i:s', $lastModified) . ' GMT');

               if (!empty($_SERVER['HTTP_IF_MODIFIED_SINCE'])
                   && strtotime($_SERVER['HTTP_IF_MODIFIED_SINCE']) >= $lastModified
               ) {
                   header('HTTP/1.1 304 Not Modified');
                   exit;
               }
           }
       }
   );
   ```

3. Сохраните файл.

> ⚠️ Если на сайте включён режим «Композитный сайт» (composite) — он управляет кешем сам;
> в этом случае Last-Modified лучше включать через настройки композита, а не через init.php.
> Если не уверены — сначала проверьте: админка → *Настройки → Композитный сайт*.

**Проверка (выполнить в терминале или попросить разработчика):**
```bash
curl -sI https://spbcons.ru/ | grep -i last-modified
# должна появиться строка Last-Modified: ...

curl -sI -H "If-Modified-Since: $(date -uR -d '+1 day')" https://spbcons.ru/ | head -1
# должно прийти: HTTP/1.1 304 Not Modified
```

## Шаг 2. Редирект URL с несколькими слешами (пункт аудита 1.3)

**Зачем:** сейчас `https://spbcons.ru//////news/` открывается с кодом **200** — это полный
дубль страницы `/news/` для поисковика. Нужно, чтобы такие адреса делали **301-редирект**
на вариант с одним слешем.

**Как (правит хостинг-провайдер или системный администратор в конфиге nginx):**

В блок `server { ... }` для сайта, **до** основных `location`, добавить:

```nginx
# 301-редирект адресов с повторяющимися слешами на канонический URL
location ~* "//" {
    rewrite ^ $scheme://$host$uri permanent;
}
```

После правки администратор перечитывает конфиг:
```bash
nginx -t && systemctl reload nginx
```

> Это серверная настройка. Если у вас нет доступа к конфигу nginx — отправьте этот блок
> в техподдержку хостинга с просьбой «добавить 301-редирект для URL с дублирующимися слешами».

**Проверка:**
```bash
curl -sI "https://spbcons.ru//////news/" | grep -iE "HTTP/|location"
# ожидается: HTTP/1.1 301 ... и Location: https://spbcons.ru/news/
```
Проверьте на 2–3 адресах: `///contacts/`, `//systems/`.

## Шаг 3. Страница /infobanki/ — убрать ошибку и наполнить (пункт аудита 2.3)

**Зачем:** на странице `https://spbcons.ru/infobanki/` прямо в теле висит красная ошибка
`Cannot find 'template1' template with page 'news'` (её видят и люди, и поисковики),
а сама страница — почти пустая «заглушка».

**Как (всё в админке Bitrix, файла в репозитории нет):**

1. Войдите в админку и перейдите: **Контент → Структура сайта → Файлы и папки → папка `infobanki`**.
2. Откройте страницу `infobanki/index.php` на **редактирование** (визуальный редактор или «Изменить как PHP»).
3. Найдите компонент, у которого в параметрах указан шаблон **`template1`** (его не существует —
   отсюда ошибка). Варианты:
   - либо выбрать у компонента **существующий** шаблон (`.default` или другой из списка),
   - либо удалить этот битый вызов компонента, если он лишний.
4. Наполните страницу полезным контентом (описание информационных банков КонсультантПлюс) —
   **или**, если страница пока не нужна, закройте её от индексации: в свойствах страницы
   («Заголовки и метаданные») добавьте мета-тег
   ```html
   <meta name="robots" content="noindex, follow">
   ```
5. Сохраните и очистите кеш (Шаг 0).

**Проверка:** откройте `https://spbcons.ru/infobanki/` — красной надписи быть не должно.

## Шаг 4. (Опционально) Перепроверить PageSpeed

После Шагов 1–3 и заливки файлов прогоните мобильный тест заново:
`https://pagespeed.web.dev/` → вставьте `https://spbcons.ru/` → **Mobile**.
Базовые узкие места (gzip, webp) уже закрыты — показатель Performance должен подрасти.

## Приложение. Список файлов для заливки (из `public_html/`)

Залить «поверх» по тем же путям (корень сайта = DOCUMENT_ROOT). Это применяет
пункты 2.1, 2.4, 4.4, 1.1, 4.1, 4.5 — их трогать в админке/конфиге не нужно.

```
/index.php
/systems/index.php
/systems/bukhgalteru/index.php
/systems/yuristu/index.php
/systems/rukovoditelyu/index.php
/systems/byudzhetnoy-organizatsii/index.php
/systems/kadroviku/index.php
/local/templates/SPBCons_New_2026/footer.php
/include/lead-pre-footer.php          ← новый файл
```

⚠️ Заливать **с перезаписью** одноимённых файлов, **без** режима «удалять отсутствующие»
(иначе пострадает ядро `/bitrix/`). Перед заливкой сделайте бэкап серверных `index.php`
и `footer.php`.
